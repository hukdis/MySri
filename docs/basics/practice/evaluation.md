# 评估与排错：区分跑通、记忆与泛化

本页供真实模型与原理实验共同查询。先看现象定位问题，再查看各次运行记录；真实预训练模型与教学小模型的数据分别保留。

训练结束不等于任务完成。最有用的检查顺序是：先确认梯度和权重确实发生预期变化，再检查训练拟合，最后检查留出对象与条件消融。

## 四层证据分别说明什么

| 层次 | 证据 | 结论范围 |
| --- | --- | --- |
| 程序跑通 | 前向、反向、保存与加载无异常 | 代码路径可执行 |
| 参数更新正确 | 可训练参数发生变化，冻结参数不变 | 冻结与优化器配置有效 |
| 训练目标拟合 | loss 下降、训练对象自由生成更好 | 对已见数据的拟合 |
| 条件与留出表现 | 未见参数组合、置零/打乱特征比较 | 当前合成分布中的条件使用与有限泛化 |

训练 loss 是用正确前序 token 计算的，而自由生成必须接着自己的输出继续。前者很低、后者仍失败，并不矛盾；要查看具体生成，不能只看一条曲线。

## 常见现象与下一步检查

| 现象 | 先检查什么 |
| --- | --- |
| loss 不降 | 答案标签是否全被忽略；学习率；可训练参数是否进优化器 |
| LoRA 首步 A 没有梯度 | B 是否零初始化；B 是否已有有效梯度；后续 A 是否更新 |
| 连接器没有梯度 | 是否误用 no_grad/detach 剪断冻结解码器的计算链 |
| 训练好、测试差 | 几何分布、数据量与组合外推；不要用测试集反复调参 |
| 格式有效、参数不对 | 分开统计半径、高度要求，检查条件变化是否对应输出变化 |
| 特征打乱后分数不变 | 模型是否忽略条件；消融是否真的改变了对象配对 |
| 保存后输出不同 | 基座、tokenizer、聊天模板和 eval 模式是否一致 |
| 显存不足 | 序列长度、batch、模型大小；不要只看 LoRA 可训练比例 |

## 比较实验时固定哪些条件

本章 SFT 与 LoRA 共用 `base.pt`、数据划分与答案损失，但未针对各方法充分搜索超参数；只适合解释参数化差异。连接器实验使用 `sft.pt`，其结果同时受解码器能力限制，不能与从随机模型开始训练的设置混为一谈。

输出记录随机种子、PyTorch 版本、步数、可训练参数、样本预测与运行时间。后者包含本机环境和首次预热影响，不能据此直接估算其他硬件或真实大模型耗时。

要研究泛化，应扩大独立对象和表达覆盖，建立更多种子与独立评价；本章 36 个圆柱和固定划分远不足以支撑论文级性能结论。

## 真实预训练模型运行 {#real-model-run}

2026-10-23 在 Windows / Python 3.13.11 / CPU 上实际加载了 SmolLM2-135M-Instruct，使用 PyTorch 2.9.1、Transformers 4.57.1、PEFT 0.17.1。模型版本为 `12fd25f77366fa6b3b4b768ec3050bf629380bac`。

运行命令对应[真实模型微调页](./pretrained)：训练 20 步，batch 为 4，学习率 0.001，LoRA rank 为 4、alpha 为 8，种子 37。训练包含 48 条描述、24 个几何；测试为 12 条描述、6 个留出几何，生成上限为 16 个新 token，使用确定性解码。

| 观察项 | 这一次运行的结果 |
| --- | --- |
| 训练前测试命令完整匹配 | 0/12 |
| 训练后测试命令完整匹配 | 12/12 |
| 训练后验证命令完整匹配 | 12/12 |
| 可训练参数 / 总参数（含 LoRA） | 1,221,120 / 135,736,128 |
| 首步 / 最后一步采样 batch 损失 | 3.40977 / 0.000743 |
| 冻结参数摘要、保存后重载输出 | 一致 |

例如测试输入 `make cylinder radius 2 height 2`，训练前回答以 `To make a cylinder...` 开头，训练后为 `CYL 2 2`。完整预测与运行条件见 [observed-pretrained-run.json](/practice-lab/observed-pretrained-run.json)。这份新记录独立于 2026-10-22 的小模型记录。

这说明真实权重在这个固定小任务中学会了目标格式和留出参数组合。数据只有 36 个圆柱、两种固定表达，且只运行一个种子；不能由此推断任意语言、复杂 CAD 或其他数据分布的效果。原模型未被提示 `CYL` 格式，因此前后比较也包含输出约定学习。

首末损失来自不同采样 batch，不是整套验证损失曲线。检查点重载一致只验证保存流程；本次没有执行 STEP/B-rep 导出。

## 旧版 CPU 小模型的验证范围 {#verification-scope}

以下记录来自 **2026-10-22** 的一次本地运行：Windows、Python 3.13.11、PyTorch 2.9.1+cpu、种子 37。教学基座预热 400 步，三个实验分别训练 400 步；测试含 12 个表达、对应 6 个独立几何。数值用于说明这份代码的行为，不是论文指标或跨硬件承诺。

| 实验 | 可训练参数 | 训练对象完整匹配 | 测试对象完整匹配 | 测试命令有效 |
| --- | --- | --- | --- | --- |
| 全量 SFT | 41,298 | 100% | 100% | 100% |
| LoRA | 4,872 | 100% | 100% | 100% |
| 只训练连接器 | 18,912 | 100% | 33.3% | 100% |

连接器的训练 loss 从约 **2.778** 降至 **0.00120**，但留出对象只匹配 **4/12 条表达**。将测试条件置零或打乱后，完整匹配均为 **0/12**。这同时说明它在这个任务中利用了条件、也说明训练拟合和有效格式并没有带来充分的组合泛化。

我们保留这个不够好的结果，而不继续按测试集调参把它做成“成功演示”。它是阅读多模态论文时很有用的对照：接口训练发生、模型使用条件、所有要求正确，是逐层更强的结论。

## 回到论文时可以提出的具体问题

读到“指令微调”，核对样本的输入、答案和损失区域；读到“多模态对齐”，核对特征来源、连接方式、冻结模块与训练目标；读到“生成质量提高”，核对候选预算、执行成功率与要求满足率。

这些问题能把本章的小实验接回 [Text2CAD](/cad/text2cad)、[CAD-Llama](/cad/cad-llama)、[CAD-MLLM](/cad/cad-mllm)、[CADTests](/cad/cadtests)。真实论文增加的任务和限制，才是继续阅读时需要逐项理解的部分。
