# FEA反馈修复能改善部分要求，却很少同时闭合几何、接口与结构验收合同

::: info 来源资料整理 · 待人工复核
依据用户提供的研究发展树第四版迁移。论文、资源与问题的来源记录不等于本站本次独立核验；AI 方法建议、验证阈值与原因解释不作为实验结果。
:::

> I-H-05 · 来源材料标记：原文支持的范围限定问题 · [CAD生成](/cad/tasks/generation)

## 实际场景与失败条件

**场景**：从工程简报生成带安装界面、受力要求和材料假设的单/多零件STEP，要求既能导出、网格化，又满足全部声明的工程指标。

**失败条件**：Son26 §5.1 Table2在50 Hephaestus-CCX案例的一次生成/一次repair下几乎无strict-pass，mean req pass虽可提高仍非全通过；不同推理预算并非单调更好。不能外推不限预算或所有FEA系统均无解。

**后果**：平均通过率可能掩盖关键接口、载荷传递或selector仍失败；几何IoU上升也不能作为工程合同闭合证据。

## 原论文证据

### Son26 · §5.1 Table2；§5.2 Table3；§6；Appendix E

20单件/30多件严格验收和一次FEA repair，mean与strict分开；多件添加interface/clearance/load-transfer/selector要求；后续多轮case不能冒作主sweep通过。

[FEA反馈设计代理](/cad/papers/son26) · [证据来源](https://arxiv.org/html/2605.17448v2)

### Sin26 · L3；Appendix D.1–D.3；Limitations

matched material/support/load/mesh与selector有效是FEA比较前提；范围限孤立零件线性静力。

[CADEngBench](/cad/papers/sin26) · [证据来源](https://arxiv.org/html/2608.09296v1)

### EXT_PhysicsLoop · §8消融；§9.2–9.5

已有物理反馈、多代理和topology optimization比较；同时报告design-space/connectivity失败及更多迭代不稳定。

[Physics-in-the-Loop: A Hybrid Agentic Architecture for Validated CAD Engineering Design](https://arxiv.org/abs/2605.19717) · [证据来源](https://arxiv.org/html/2605.19717v1)

## 已有方案与剩余边界

### Son26

[FEA反馈设计代理](/cad/papers/son26)

**已经解决**：已有蓝图、21视图、FEA repair及更具体反馈。

**边界**：不能把加FEA或typed blueprint本身当创新；比较相同交互预算的合同全闭合。

### EXT_PhysicsLoop

[Physics-in-the-Loop: A Hybrid Agentic Architecture for Validated CAD Engineering Design](https://arxiv.org/abs/2605.19717)

**已经解决**：已有物理反馈闭环，部分任务能达到目标。

**边界**：不同数据/假设不可跨表比较胜负；不能用Son结果否定该方法。

### EXT_LMBuild

[LMBuild: Evaluating LLM Agents for Generating Buildable and Functional Structures](https://arxiv.org/abs/2610.04292)

**已经解决**：已有rigid物理与功能评测。

**边界**：不建模弹性/疲劳等，不能替代声明材料/载荷的结构FEA。

在已核Hephaestus-CCX合同与交互预算中，联合满足仍困难。拟研究基于失败原因的最小修复和保持，作用范围限可操作的线性静力及接口，不承诺通用机械安全。

## 原因解释与待验证方法


**来源材料中的机制解释**

- 多个类型要求有不同失败来源；部分模型feedback后仍回退；单次部分满足不等于严格通过。


**待验证的原因假设**

- 将selector/连通/接口失败与真实结构不足分流，并保护已满足约束，可减少盲目重生成破坏已完成部分。


### 分层合同与最小修复

**实施机制**：先验单位、solid/接口连通、load/support selector绑定，再运行FEA；把失败切为几何绑定/数值求解/结构超限，不同类限制不同修改动作；每轮保留已满足硬要求。

**相对近邻的拟议变化**：已有FEA feedback之上，验证分流和不变量保持在同预算下的作用。

**成立条件**：需求、材料/载荷有独立来源，selector可落在几何上。

**失败风险**：LLM或规则错误分流；保护太多导致无法达到结构目标。

### 网格与载荷敏感性终验

**实施机制**：在候选冻结后使用更细mesh和一个预先声明载荷扰动，检查改善是否仅来自网格/selector伪差；训练/修复看不到终验。

**相对近邻的拟议变化**：避免把同一粗solver返回的奖励当独立工程证据，不宣称覆盖任意物理。

**成立条件**：能负担少量高精度参考，线性静力适用。

**失败风险**：奇异应力、错误边界物理假设仍可能使终验无意义。

## 数据与标注安排


**数据安排**

Hephaestus-CCX数据和可执行环境入口需在实施前核对；起步采用原创支架、板和孔结构及明确安装区/载荷合同，自建受限线性静力小样本，不冒称原榜单复现。


**所需标注**

工程合同、typed失败原因、有效selector和网格收敛参考


**构造方式**

若原benchmark可用按其合同；否则先自建20–30支架/板/孔结构与明确安装区域，每件2载荷，外加少数2–3体接口例。


**许可说明**

自建规则与几何来源记录；公开benchmark按原许可，不把原测试合同作训练数据。


**来源与泄漏控制**

按几何template及load family隔离；同piece多mesh是同一任务，不增加独立样本数。


## 最小验证与否定条件

以下均为计划，不是已完成实验或学术创新结论。


**可证伪假设**

分层失败分流与保护已满足项能在同FEA/token预算下提高合同全通过。


**比较基线**

- 原文式FEA repair
- typed blueprint+同样反馈
- 无分流完整重生成
- 纯规则参数优化


**数据划分**

同初始artifact和交互预算配对；开发/终验geometry、load family分开；严格失败全计。


**指标**

- strict pass
- 各typed requirement pass
- 已通过项回退
- selector/mesh失败率
- 稳健终验通过
- 总FEA/token/CPU成本


**消融**

- 去分流
- 去已满足项保护
- 去冻结终验
- 同预算随机重试


**预设支持判据**

strict-pass与稳健终验均提高，不靠只移除难要求；FEA不成功的案例纳入分母。


**否定或收缩条件**

只有mean req pass提高、strict不变；或高精度/扰动终验抵消全部收益。


**最小起步规模**

20–30明确单件合同+少量多件作为pilot；运行profiling后确定正式scale。
