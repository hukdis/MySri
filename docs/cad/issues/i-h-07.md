# 装配说明与产品图一致，也可能给出几何上无法插入或不稳定的步骤

> I-H-07 · 研究问题 · [CAD理解、评估与规划](/cad/tasks/analysis)

## 实际场景与失败条件

**场景**：从STEP和BOM生成面向人的装配说明，文字中的零件、数量和顺序正确，但实际操作还需要可达方向、工具通道和中间支撑。

**失败条件**：装配说明原文§8.1–8.3/8.8明确只提取labels/bboxes/containment、flatten层级，mates部分来自结构输入；acyclic order不能等同collision-aware order。GLARE已有碰撞路径和人工纠错，但§5只平移拆解、不考虑重力/摩擦/稳定性。

**后果**：语言和图的相互一致可能掩盖无法插入、倒塌或需要未声明支撑的步骤；自动QA在现有原型中主要指引人工注意。

## 已有方案与剩余边界

### Har26b

[CAD关系与机器人装配规划](/cad/papers/har26b)

**已经解决**：已有学习关系+几何符号planner，不能说缺乏CAD几何顺序规划。

**边界**：其定位不是语言说明；平移逐件且不测稳定性。

### EXT_Ant26

[A Neuro-Symbolic Framework for LLM-Driven Task Planning and Execution in Industrial Assembly](https://doi.org/10.3390/ai7100395)

**已经解决**：已有正式HTN/BT及执行恢复。

**边界**：只4类已校准任务，不能证明任意CAD到说明的几何完整性。

### EXT_LMBuild

[LMBuild: Evaluating LLM Agents for Generating Buildable and Functional Structures](https://arxiv.org/abs/2610.04292)

**已经解决**：已有离散插入路径/中间支撑和rigid模拟验证。

**边界**：缺完整CAD工艺语义/工具通道；不能把其可构造分数当专家说明质量。

在所核STEP说明原型中，产品图grounding尚未连接可执行几何顺序与中间状态；拟以已有planner为validator接到说明生成，而非新造一个仅语言评分器。广泛工业泛化仍未证明。

## 原因解释与待验证方法

**来源材料中的机制解释**

- bboxes/containment和无环先后图不足以表示路径/支撑；原型层级被flatten。

**待验证的原因假设**

- 把顺序的几何前置条件与支撑状态做成可追溯step证据，能减少语义一致但不可操作的说明。

### 先验证动作再写说明

**实施机制**：在ProductGraph中保留subassembly；每步绑定具体实体、插入方向、碰撞检查结果和必要支撑；通过有限几何validator后再让LLM表述，未能验证项明确交人工。

**相对近邻的拟议变化**：语言端仅表述已验证动作，与只检查文字引用/无环顺序不同；复用GLARE/物理构造已有工具。

**成立条件**：任务先限刚性小装配和已知简单插入motion。

**失败风险**：解析接触/公差或摩擦未建模，validator仍不能承诺真实可装。

### 失败驱动最少人工补证

**实施机制**：当缺mate/插入方向/扭矩字段时，提出针对该步骤的具体补充项；保存纠错证据而不自动把每次人工编辑当训练真值。

**相对近邻的拟议变化**：把人工需求绑定到可验证缺口，减少无目标的全篇人工审核。

**成立条件**：有少量专家可检查。

**失败风险**：错误的人类补证会被系统固化。

## 数据与标注安排

**数据安排**

- DS_F360_Assembly

**所需标注**

先后关系、路径、临时支撑、工具通道与专家说明

**构造方式**

先自建20–30个3–8件刚性小装配，控制可装/被挡/需支撑版本；公开Gallery仅在许可与必要mates可读时补充。

**许可说明**

按原模型条款；自建装配程序与说明单独标注许可。

**来源与泄漏控制**

按装配template及零件族分组，同结构仅交换名称/顺序不当独立测试。

## 最小验证与否定条件

以下为验证方案，所列阈值是预设判据。

**可证伪假设**

动作证据绑定+几何前置验证减少不可执行说明，同时不只靠拒绝输出提高精确率。

**比较基线**

- ProductGraph grounded LLM+规则QA
- 几何planner无LLM说明
- 文本自检
- 语义图完整但无支撑检查

**数据划分**

按assembly family留出；step级依赖同组；固定human query和token预算。

**指标**

- 完整序列可执行率
- grounding错误
- 碰撞/支撑违规
- 拒绝/人工补证率
- 专家可理解性
- 总成本

**消融**

- 去路径检查
- 去支撑状态
- flatten vs 层级
- 去证据绑定

**预设支持判据**

在相同覆盖率下几何违规减少、人工补证更少；blind专家评审与模拟结果分开。

**否定或收缩条件**

仅靠全部拒绝或人工替代实现提升；规则planner已足够无需LLM。

**最小起步规模**

20–30小装配×2–3受控变体；不进行真实机器人或安全关键部署。
